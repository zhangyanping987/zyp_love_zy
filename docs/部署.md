# 部署说明

这个相册是静态站点。构建之后只需要把 `dist/` 里的文件放到能托管网页的地方。图片和视频已经打进包里，服务器不用再连抖音。

内容来自抖音账号「曾妍」等本地素材。页面有前端口令；公开部署时请只把链接发给信任的人，勿提交到会被广泛传播的目录站。

## 目录

| 路径 | 作用 |
|------|------|
| `public/media/images/` | 图文作品的 webp |
| `public/media/videos/` | 5 条 mp4 |
| `public/media/posters/` | 视频封面，球面上显示这张图 |
| `public/photos.json` | 相册清单，页面启动时读取 |
| `dist/` | `npm run build` 生成的可部署文件 |

`vite.config.ts` 里 `base` 是 `./`。资源用相对路径，所以放在网站根目录或任意子目录都可以，不必改配置。

## 1. 本机开发

需要 Node.js 20 或以上。

```bash
cd ~/Projects/zy-album
npm install
npm run dev
```

终端会打印本地地址，一般是 `http://127.0.0.1:5173/`。改代码会自动刷新。

打开后先关掉说明卡片，等照片铺开。拖拽旋转，滚轮缩放，点缩略图全屏。缩略图右下角有 ▶ 的是视频，点开后会播放。

## 2. 本机静态预览

和正式部署用的是同一份文件：

```bash
npm run build
npm run preview
```

`preview` 默认也是 `http://127.0.0.1:4173/`。确认图片能出来、视频能播放，再往下部署。

## 3. 用 Nginx 挂在本机或局域网

```bash
npm run build
sudo mkdir -p /var/www/zy-album
sudo cp -a dist/. /var/www/zy-album/
```

站点配置示例（监听 8088，只给本机和局域网用）：

```nginx
server {
    listen 8088;
    server_name _;
    root /var/www/zy-album;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~* \.(webp|jpg|mp4)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

然后：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

浏览器打开 `http://<这台机器的IP>:8088/`。

视频是 mp4。Nginx 默认就会按范围请求返回，拖动进度条一般没问题。如果播放器一直转圈，检查该 location 没有关掉 `Accept-Ranges`。

不要把这个端口映射到公网。

## 4. 只拷 dist 到另一台电脑

`dist/` 是完整站点，不需要 Node。

```bash
npm run build
tar -C dist -czf zy-album-dist.tar.gz .
```

在另一台机器解压到任意目录，用任意静态服务器打开，例如：

```bash
tar -xzf zy-album-dist.tar.gz -C /path/to/site
python3 -m http.server 8080 --directory /path/to/site
```

不要直接双击 `index.html`。相对路径在 `file://` 下经常加载失败。

## 5. GitHub Pages（公开访问）

站点带前端口令（`src/constants/access.ts`），仓库可以设为 **Public**，方便把链接发给别人。注意：口令只挡页面入口，**挡不住**直接打开 `media/` 下的图片/视频 URL；链接只发给信任的人。

1. 在 GitHub 新建仓库（Public 即可），名字随意。
2. 本地首次推送：

```bash
cd ~/Projects/zy-album
git add .
git commit -m "Add Zeng Yan 3D album"
git branch -M main
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main
```

3. 仓库 Settings → Pages → Source 选 **GitHub Actions**。
4. 推到 `main` / `master` 后，Actions 里的 “Deploy to GitHub Pages” 会执行 `npm ci` 和 `npm run build`，再发布 `dist/`。
5. 部署完成后，Pages 页面会给出地址，形如 `https://<用户名>.github.io/<仓库名>/`。打开后先输入口令，再看信和相册。

工作流文件是 `.github/workflows/deploy.yml`。因为 `base` 已经是 `./`，仓库名和地址前缀不用写进配置。

文件较大时注意仓库容量：当前 `public/media` 大约九十多 MB，单文件勿超过 100MB。

若以后改成不想公开源码，可把仓库改为 Private；Pages 对免费账号私有站的访问权限以 GitHub 当时规则为准。

## 6. 以后换一批素材

1. 图片放进 `public/media/images/`，视频放进 `public/media/videos/`。
2. 给每个视频抽一帧封面：

```bash
ffmpeg -y -ss 0.4 -i public/media/videos/新视频.mp4 \
  -frames:v 1 -update 1 public/media/posters/新视频.jpg
```

3. 在 `public/photos.json` 追加一条。图片：

```json
{
  "url": "media/images/新图.webp",
  "title": "标题",
  "kind": "image"
}
```

视频：

```json
{
  "url": "media/posters/新视频.jpg",
  "thumbUrl": "media/posters/新视频.jpg",
  "title": "标题",
  "kind": "video",
  "videoUrl": "media/videos/新视频.mp4"
}
```

路径不要加开头的 `/`。页面会按站点根目录自动补上。

4. 重新 `npm run build`，把新的 `dist/` 覆盖到服务器。

## 7. 构建失败时

- `npm ci` 报 lock 文件不同步：在项目目录执行一次 `npm install`，再提交更新后的 `package-lock.json`。
- 页面空白：看浏览器控制台里 `photos.json` 是不是 404。用 `base: './'` 时，不要把站点挂到和 `index.html` 不在同一层的路径上却漏拷文件。
- 视频封面是黑的：用上面的 ffmpeg 命令重新抽帧，`-ss` 可以改成 `1` 再试。
